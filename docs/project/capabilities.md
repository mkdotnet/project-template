# Project Capabilities

## Purpose

Stable capability-level view of what the template currently provides. Adopting projects replace this with product/system capabilities.

| Capability | State | Notes |
| --- | --- | --- |
| Technology-neutral governance overlay | Available | Governance/docs/AI are separate from product topology. |
| Portable implementation boundary | Available | Complete product workspace lives under `implementation/`. |
| Framework-native topology | Available | Internal implementation structure is owned by the selected framework/project. |
| Multi-assistant AI collaboration | Available | Codex, Claude Code, and Cursor share one repository contract. |
| Structural code intelligence | Available by policy | Graphify targets implementation by default. |
| Optional broader code search | Optional | Sourcegraph is deliberately adopted only when useful. |
| Progressive context routing | Available | Agents load only task-relevant context. |
| Long-term delivery-state recovery | Available | Roadmap/status/capabilities expose current state. |
| Focused debug/refactor context | Available | Module context + Graphify + exact implementation/tests + relevant decisions. |
| Repository-contract validation | Available | Mechanical checks and low-noise advisories are automated. |
| Conditional security/compliance context | Available when triggered | No speculative regulatory content is created. |
