# Developer Guides

## Purpose

This area contains practical documentation a developer needs to work with the project. It complements architecture and standards; it does not duplicate them.

Adopting projects should add focused pages only when real procedures exist, for example:

- getting started and local prerequisites;
- development environment setup;
- build and run instructions;
- configuration and local data dependencies;
- testing and debugging procedures;
- database or migration operations;
- deployment or operational procedures used by developers;
- extension points and common troubleshooting.

## Rules

- Keep instructions executable and current.
- Link to architecture or standards rather than copying their explanations.
- Do not place secrets or environment-specific credentials in guides.
- Prefer one focused page per durable procedure once this index becomes too large.
- Remove obsolete procedures rather than preserving historical setup paths.

A new developer should be able to start from this index and find the practical path to build, run, test, debug, and safely change the project without reading every architecture document.
