# User Guides

## Purpose

This area contains documentation for people who use or administer the delivered product: operators, administrators, customers, support staff, or other end users.

Adopting projects should organize user documentation around real roles and workflows. Typical focused pages may cover:

- getting started;
- common workflows;
- feature usage;
- administration and configuration exposed to users;
- troubleshooting and recovery actions;
- FAQ or operational limitations.

## Audience and Language

Use the language appropriate to the target audience. If the project must maintain multiple languages, introduce locale folders such as `fa-IR/` or `en-US/` only when those variants can be kept current.

## Rules

- Describe supported user behavior rather than internal implementation detail.
- Keep screenshots, examples, and workflows aligned with the current product.
- Keep developer-only setup in `docs/guides/developer/`.
- Do not expose internal credentials, private endpoints, or sensitive implementation details.
- Add a focused document only when a real user role, workflow, or support need justifies it.
